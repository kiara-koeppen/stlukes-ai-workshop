# Medication Diversion Support: Attendee Guide

## The Problem (TL;DR)

Every month, St. Luke's Diversion Support Team investigates 1-6 suspected medication diversion cases. Each investigation currently takes 3-5 manual days: investigators build Excel pivots, manually compare a suspected employee's dispensing/administering/waste activity to peer norms, flag anomalies (waste without witness, administrations without matching orders, opioids with no pain score, off-shift activity), and document findings in prose. The work is repetitive, hard to standardize, and delays investigations.

## What You'll Build + Which Databricks Assets

Over the next 2-3 hours, you'll build a peer-benchmarked anomaly detection system that ranks employees by risk and generates investigation narratives in seconds. You will use:

- **Metric Views** (Unity Catalog): Aggregates medication activity by employee, encoding anomaly rules as measures (Waste Without Witness, Administration Without Order, Opioid Low Pain Score, Composite Score).
- **AI Functions** (`ai_query`): Generates 3-sentence investigation narratives comparing the employee to peer-group norms, using real IRIS scores.
- **Genie Agent** (natural-language SQL): Answer questions like "Who are the top anomalies?" or "How does Sarah's waste pattern compare to her peer group?"
- **AI/BI Dashboard** (Lakeview): Visualization of employee rankings, anomaly heatmaps, and peer comparisons.
- **(Stretch) Databricks App**: Investigator UI for documenting findings and surfacing Genie reasoning in real time.

## Genie Code Prompts to Get Started

These are natural-language queries you'll ask a Genie Agent to explore the data:

### Prompt 1: Find the Top Anomalies
```
Show me the top 10 employees by Composite Anomaly Score, with their Dispense Count, 
Waste Without Witness CII, and Administration Without Order counts.
```
Genie will translate this to SQL over your metric view, rank employees, and show you where the risks are.

### Prompt 2: Peer Benchmarking
```
For employee EMP-00001, show me their Waste Without Witness CII and Opioid Low Pain Score 
compared to other oncology nurses on the night shift.
```
Genie drills into your metric view dimensions (Department, Role, Shift) and compares peer means.

### Prompt 3: Rules-Based Drill
```
Which employees have more than 5 Waste Without Witness CII transactions?
```
This tests the explicit anomaly flag you encoded in the metric view.

### Prompt 4: Narrative Lookup
```
What investigation narratives were generated for the top 5 employees by anomaly score?
```
Genie queries the AI-generated narratives table and returns prose explaining why each person is flagged.

### Prompt 5: Temporal Pattern
```
Which employees have the most Off Shift Activity Count?
```
Behavioral anomaly; often correlates with diversion patterns.

## From POC to Production

### Governance & Access Control

**Workshop context:** You're building in `kk_test` with synthetic data (no PHI). In production, this moves to `healthcare_ai` catalog.

**Production changes:**
- **Unity AI Gateway** (Databricks' governance layer): Controlled-substance investigations are HR and legal sensitive. The production version will run under the Gateway, which enforces:
  - Rate limits (e.g., max 10 investigations per day to prevent abuse).
  - Audit trails: every query logged with user, timestamp, and employee name searched.
  - Guardrails (Public Preview): optional PII/sensitive-term flagging.
- **RBAC:** Only the Diversion Support Team (+ legal/compliance) can query this schema. Define a UC role, grant SELECT on `med_diversion.*` to that role.
- **No Patient PHI:** The diversion data includes medication + timestamps + employee ID, but no patient diagnoses or treatment plans. Compliance verified.

### Investigation Workflow Enhancement

**Stretch:** Integrate investigation findings with your compliance workflow:
1. Investigator uses the app/dashboard to review the narrative and anomaly breakdown.
2. If they confirm diversion, they log the case in your HRIS or compliance system (e.g., Workday, Veradigm).
3. Genie Agent queries this schema for historical patterns: "How many investigations involved EMP-00001 in the last 2 years?"
4. MLflow evaluation: After the investigation concludes, the investigator marks the narrative as "helpful" or "misleading"; you use MLflow to score narrative quality and tune the ai_query model selection.

### Moving Diversion Narratives into Your Operational System

The narratives generated by `ai_query` are human-readable summaries meant to inform, not replace, human judgment. To operationalize:

1. **Export narrative + metadata** to your HIRS or case-management system via Databricks SQL connector or REST API.
2. **Lakebase (production path):** If the Diversion Support Team wants to store notes or follow-up actions linked to investigations, use **Lakebase Provisioned** (Databricks managed Postgres) for transactional storage. The App writes investigator notes to Lakebase; a synced Delta table feeds the analytics layer (Genie Agent, dashboard).
   - Example: investigator enters "Confirmed diversion; referred to legal" in the App; Lakebase transaction stores it; a Lakeflow sync pulls it back to Delta daily so Genie can query "How many cases have been referred to legal this quarter?"

### Extending the Data

**Teams/Slack integration (future):**
- **Lakeflow Connect (in beta):** Ingest HIRS audit logs, external compliance alerts, or Epic orders to enrich medication_activity.
- **Slack workflow:** When an investigation is filed, post a Slack message to `#compliance` with the top 3 anomalies and the narrative. Investigators click "Start Genie Agent" to drill into peer comparisons live.

### MLflow Evaluation of Narratives

After running 10-20 investigations, measure whether the ai_query narratives are actually helping:

1. **Evaluation dataset:** For each narrative, the investigator marks: "Accurate and useful", "Misleading", "Missing key anomaly".
2. **Scorer function:** Use MLflow's built-in scorers (Correctness, Groundedness) + a custom scorer that checks: "Does the narrative mention all flagged anomalies?" and "Is the peer-group comparison fair?"
3. **Fine-tune model selection:** If narratives on CII waste are weak with llama-3-3-70b, experiment with claude-3-5-sonnet (via ai_query model param).
4. **Continuous improvement:** Re-run evaluation quarterly as diversion patterns shift.

## Key Assumptions & Constraints

- **Synthetic data for the workshop:** Real medication_activity data comes from Omnicell + Epic integration. The 45k events here are synthetic with planted signal.
- **IRIS scores:** ControlCheck scores are mocked. In production, ingest real scores from Bluesight.
- **Peer groups:** The 10 peer-group cohorts (by role + unit + shift) are illustrative. In production, define these with the Diversion Support Team (might be by facility + department + credential level).
- **Narrative length:** The ai_query prompt is tuned for 3-sentence narratives. Longer narratives (e.g., 5-sentence case summaries) may timeout; if so, narrow the input (aggregate to weekly instead of all-time).

## Troubleshooting

**Q: My metric view is slow / dashboard is slow.**
A: The metric view aggregates 45k raw events. If you see slowness, check that your Genie Agent or dashboard is NOT directly querying `medication_activity`; it should query `diversion_metrics` (pre-aggregated). Also, the metric view groups by all dimensions by default; if you drill into many dimension combinations, you get a Cartesian explosion. Stick to filtering on Employee + Role for best performance.

**Q: The investigation narrative is blank or garbled.**
A: The `ai_query` prompt is multi-line; check for syntax errors in the CONCAT. Also, `ai_query` is subject to rate limits and may time out if you run it on all 50 employees at once. The solution creates narratives only for the top 5 (LIMIT 5) for speed; in production, run this as a nightly batch job on new diversion flags.

**Q: Can I see the SQL Genie generated?**
A: Yes! In the Genie UI, after you ask a question, click "View SQL" to see the Genie Code translation. You can then copy it into a notebook to refine or troubleshoot.

**Q: What if a narrative mentions an employee who was actually cleared?**
A: The narrative is generated from the metric view anomaly flags, which are rule-based. If a rule is overfitting (e.g., "Admin Before Order" fires on order_datetime edge cases), the narrative will too. Work with your compliance team to refine the rules in the metric view; that's a product improvement, not a data quality issue.
